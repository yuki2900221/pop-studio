# 技術選定と構成

## B5面付け・連続入力（2026-11-07）

用紙は日本の[JIS B5 182 × 257 mm](https://faq2.epson.jp/web/Detail.aspx?id=50971)を基準にします。B5は横1面、1/2は縦1列2段、1/4は横2列2段、1/8は縦2列4段です。`b5Layouts`で仕上がり寸法と印刷用紙の寸法を分け、編集画面の寸法表示と印刷待ちの面付けに使います。以前のA4・A5・棚札データは無言で変換しません。

追加時の商品を独立したスナップショットとして`pop-studio.print-queue.v1`へ保存します。保存データを実行時検証し、100商品・合計200枚・各商品1〜20枚を上限とします。次の商品へ進むときは書式と税設定を保ち、商品情報・メモ・画像を空にします。待ち一覧から再編集した内容は画面移動時にも検証して更新し、古い価格や枚数を残しません。印刷画面を開いただけでは待ち一覧を消しません。

`buildPrintSheets`がサイズ別にまとめ、同じグループ内の入力順を保って用紙を埋めます。余った枠を複製商品で埋めることはしません。プレビューと印刷は同じページ配列・共有SVGを使用します。新しいPDFライブラリやバックエンド保存を追加せず、[CSSの名前付きページ](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@page)で用紙ごとの縦横を指定します。印刷用の枠はmm単位で配置し、全商品の書体・画像が揃ってからネイティブ印刷を開きます。

## 店舗特売書式の追加（2026-11-07）

利用者の参考画像をもとに、白地、傾けた赤黒の見出し、上部の商品名、左の産地・容量・メモ2、青のメモ1、赤い税抜価格、下部の税込価格を共有SVGで構成しました。各項目を文字として編集できます。

日本語にはFONTDASUの[Mochiy Pop One（公式配布）](https://github.com/google/fonts/tree/main/ofl/mochiypopone)、金額の数字には[Archivo Black（公式配布）](https://github.com/google/fonts/tree/main/ofl/archivoblack)をSIL Open Font License 1.1で同梱しています。数字を横に引き伸ばさず、フォントの字幅で配置し、桁数が多い場合は縮小します。自己配信した両WOFF2をPNGのSVG内にも埋め込み、印刷はFontFaceSetで両書体の読み込み完了を確認します。

`memo1`と`memo2`は各40文字の省略可能な文書項目です。従来の保存データとの互換性を維持し、JSON読み込みでも型・長さ・制御文字を検証します。店舗書式は現在B5を既定にし、以前のA4横・A5横も読み込み・印刷できます。

## 目的と対象

食料品小売店で、専門的なデザイン操作を覚えずに商品POPを作成・印刷するためのWebアプリです。WindowsのEdge・Chromeを主な利用環境とし、「テンプレート選択 → 商品情報入力 → プレビュー → 保存・印刷」の流れに整理しています。

UIの説明は操作に必要なものに絞り、宣伝用のキャッチコピーをアプリへ追加しない方針です。POP上の見出しラベルは編集でき、空欄で非表示にできます。AIに広告文を生成させる機能はありません。

## データの流れ

```text
WindowsのEdge / Chrome
  ├─ React UI / 商品フォーム
  │    ├─ 同じPopArtwork SVG → 編集プレビュー
  │    ├─ 同じPopArtwork SVG → 原寸印刷 / PDF保存
  │    ├─ Canvas変換 → PNGダウンロード
  │    └─ 検証済み文書 → localStorage / JSONダウンロード
  │
  └─ 利用者がAIを実行
       └─ POST /api/ai/assist { task: "extract", text }
            └─ Cloudflare Worker
                 ├─ 同一オリジン / サイズ / 入力検証
                 ├─ Rate Limiting binding
                 ├─ Workers AI binding → Gemma 4
                 └─ JSON構造と入力由来の値を検証 → 確認画面
```

静的画面はWorkers Static Assetsで配信し、`/api/*`はWorkerを先に実行します。`GET /api/health`はAPIとbindingの有無を返します。AIが利用不可でも、商品情報の手入力・保存・印刷を継続できます。

## 保存・認証の判断

現時点ではD1、R2、KVを使用していません。保存対象は端末内の下書きと画像であり、サーバーに文書を保管しないためです。共有文書DBやクラウド画像保管を先に用意すると、店舗間のアクセス制御、バックアップ、保管期限、費用管理が必要になります。

ログインは実装していません。サーバー上の個人別文書がない段階で、形式だけのログイン画面やクライアント内のフラグを認証として扱わないためです。将来、共有・同期が必要になった場合は、利用者の条件どおりGoogle認証のみを候補とし、サーバー側のセッション検証と店舗・利用者単位のアクセス制御を実装してからD1・R2などを追加します。

同一端末・同一ブラウザプロファイルを使う人は保存済み文書へアクセスできます。localStorageは機密情報の保管庫ではありません。個人情報・秘密情報を商品メモや下書きへ入れない運用を想定しています。

## AIの境界

- 入力は1〜1,000文字、HTTP bodyは8,192バイト以下です。
- 出力は商品名・産地・単位・本体価格の4項目のみです。文章にない値は`null`を要求します。
- 価格は0〜1,000,000円の整数に制限します。出力JSONの項目、文字長、制御文字、価格を検証します。
- 文字列が元の入力に含まれるか、価格が入力中の金額と一致するかを確認します。これは正確性を保証するものではないため、反映前に利用者が確認します。
- 同一オリジンを検証しますが、Originヘッダーは一般のHTTPクライアントでも作成でき、認証の代わりにはなりません。公開AI APIの悪用対策はrate limitと入力・出力制限です。
- 生成上限は350トークン、Worker側の応答待ちは20秒です。タイムアウトやエラー時に架空の成功データを返しません。応答待ちの終了が、プロバイダー側の推論・課金まで取り消す保証はありません。
- 外部AIの応答は信頼せず、画面へ直接HTMLとして挿入しません。

## 利用枠と費用

2026-11-07に公式資料を確認した時点で、Workers AIには1日10,000 Neuronsの無料割り当てがあります。リセットはUTC 00:00、日本時間09:00です。無料割り当ては回数固定ではなく、モデル・入力・出力量で消費が変わります。無料枠を超えて使用するには有料プランが必要で、有料プランでは超過分が従量課金になります。

Workers Freeは100,000リクエスト/日、CPU時間10ms/回という上限があります。静的アセットとAPIでは計数・実行条件が異なるため、実際のアカウント契約とダッシュボードで確認してください。既存アカウントが有料プランの場合に「必ず無料」とは扱いません。

この実装作業では、課金プラン変更、独自ドメイン購入、新しい有料サービスの有効化を行う設計にはしていません。AI bindingはリモート資源を利用するため、開発時の実推論も利用量を消費します。

Rate Limiting bindingはCloudflare拠点ごとの概算カウンターです。反映に遅れがあり、設定回数を超えて許可される場合があります。IPを共有する店舗では複数端末が同じ枠を消費する場合もあります。これは厳密な支出上限や世界共通の利用枠管理ではありません。

## 現在の範囲と制約

- 用紙はB5の1・2・4・8面付けと、以前のA4・A5の縦横・棚札148 × 52 mm。自由寸法、メーカー品番別のラベル用紙DB、異なる大きさを1枚に混ぜる面付けは含みません。
- ドラッグ操作による自由配置ではなく、構造を保ったテンプレート編集です。ラベルマイティ形式の読み書きやバイナリ互換性はありません。
- 印刷はブラウザとプリンタードライバーの設定に依存します。ふちなし印刷・カスタム用紙への対応は機種で異なります。
- PNGは画像です。再編集にはJSONを使います。
- 下書きは最大100件、印刷待ちは別枠で100商品・合計200枚で、ブラウザの空き容量にも制限されます。別ブラウザ・別端末・シークレットモードへ自動同期しません。
- 画像アップロードはPNG・JPEG・WebP、4MB以下。長辺1,200px以内へ縮小して保存します。
- 税込表示はPOP上の参考表示として選択した端数処理を適用します。会計・レシートの合計税額を計算する機能ではありません。
- OS・ブラウザ・プリンターごとの実測確認と、AIモデルの出力品質は、自動テスト合格とは区別して記録します。
